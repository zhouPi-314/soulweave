# ADR-6：Web 与远程访问

- **状态**：已接受（S8 起点）
- **日期**：2026-11-01
- **决策者**：项目负责人
- **相关**：需求 §8、§7.5、§7.13；架构 §3 §6；D10、D25、D52

## 背景

需求要求手机 Web 能做「角色展示、文本/实时语音、记忆/社交/状态管理和主要控制台功能」，
同时要求「不默认公开数据库、DSH、管理 API」，并要求认证、会话保护与 HTTPS/可信隧道策略。

桌面端的全部业务能力目前只通过 221 个 ipcMain 通道暴露给本机渲染进程，
本机渲染进程是可信的（同机、同用户、contextIsolation + preload 白名单）。
把同样的通道开放给局域网，等于把「谁能连上端口谁就能控制这台电脑」当成默认值。

## 决策

### 1. 服务默认关闭，且默认只监听回环

- `enabled` 默认 false；开启后默认 `host = 127.0.0.1`
- 要局域网必须显式改 host 为 `0.0.0.0` 或具体网卡地址，并勾选风险提示
- 永远不默认监听 `0.0.0.0`

### 2. 认证用设备配对，不用账号密码

- 桌面生成 6 位配对码（5 分钟、一次性、错 5 次作废）
- 手机输码换 32 字节设备令牌；服务端只存 sha256
- 设备令牌换短命会话令牌（闲置 30 分钟 / 绝对 12 小时）
- 令牌比较一律 `crypto.timingSafeEqual`
- 失败退避 1s→60s，10 次锁 15 分钟，全部写审计

理由：单用户本机应用的密码必然弱、必然复用，且无法撤销单台设备；
配对模型天然可撤销、可审计、无需用户设置密码。

### 3. Web 路由是白名单，不是 IPC 镜像

**明确禁止**实现 `/api/ipc?channel=xxx` 这类通用代理。
一旦存在，S8 全部权限设计归零，因为任意通道都能被调用。

路由清单见 S8_实施方案.md §6，每条都声明所需作用域。

### 4. 作用域分级，管理员级必须回桌面批准

| 作用域 | 默认 | 获取方式 |
|---|---|---|
| view / chat / memory:read / social:read | ✅ | 配对即得 |
| memory:write / admin | ❌ | Web 发起申请 → 桌面弹窗点「批准」 |

这就是需求「高风险本机授权需额外安全校验」的落点：
高风险作用域的授权动作只能发生在**本机、有人在场**的桌面上。

### 5. Web 端永久没有的能力

本机文件读写、命令执行、密钥读取、角色删除、数据库操作、截图授权、组件安装。
这些是 L4/L5，Web 端连入口都没有，不是「有入口但被拒」。

### 6. 不做内置 HTTPS，远程一律走 Tailscale

- 回环/局域网允许明文 HTTP，但界面必须常驻「未加密」提示
- 不做自签证书：手机端体验极差，且训练用户养成忽略证书警告的习惯
- 跨公网的正解是 Tailscale（或等价隧道），隧道自身加密，我们不重复造轮子
- 应用内只做**探测与状态展示**（是否在 Tailscale 网段、当前连接方式）

### 7. 业务只走一条路，额度由 Core 独占

Web 的每一条聊天/语音请求都转换为带 `origin_type = user_direct`（或讨论）的 Core 事件，
与桌面、QQ 走**同一个** task-machine 与额度预留。
入口只负责身份与来源标记，不自行计数、不自行判断是否免额度。

### 8. 服务代码独立成模块

`src/main/index.ts` 已 33 万字节。Web 服务放 `src/main/web-server.ts`，
通过一个窄接口 `WebApiHost` 与主进程交互（只注入真正需要的几个函数），
不 import index.ts，也不允许 index.ts 把大段逻辑搬进来。

## 后果

**正面**
- 局域网上的陌生人即使连上端口，也只能看到登录页
- 设备可单台撤销，撤销立刻踢掉该设备所有会话
- 权限边界清晰，Web 不构成任何权限旁路

**负面 / 代价**
- 用户要在手机和电脑之间输一次 6 位码（一次性成本）
- 手机换浏览器/清缓存后需要重新配对（设备令牌存在 localStorage）
- 不做自签 HTTPS，意味着纯局域网明文——已在界面明示

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 账号 + 密码 | 单用户场景密码必弱；无设备粒度撤销；增加撞库面 |
| 只允许回环（不做局域网） | 不满足需求 D10/D25「手机 Web」 |
| 直接反代 ipcMain | 权限模型完全失效 |
| 内置自签 HTTPS | 手机端体验差，且训练用户忽略证书警告 |
| 用 JWT 无状态会话 | 撤销设备需要额外黑名单，反而更复杂；内存会话足够 |
