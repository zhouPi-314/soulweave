# AIRI 与 QQ 适配器审计（D59.02）

## 1. AIRI

| 项 | 事实 | 结论 |
|---|---|---|
| AIRI 是什么 | 日本 moeru-ai 的开源 AI 角色项目（TypeScript monorepo） | — |
| 我们与它的关系 | 架构参考 + Live2D 组件同栈实现（ADR-1 记录"复用其 Live2D 组件 10,737 行"） | 需按 MIT 履行义务 |
| AIRI 的许可证 | MIT | 允许商用、修改、再分发；**要求保留版权声明与许可文本** |
| 代码里的痕迹 | `src/renderer/live2d/cubism-app/*.ts` 头部是 `Copyright(c) Live2D Inc.`（Cubism SDK 原始声明） | Cubism 声明已保留 ✅ |
| 是否保留 AIRI 声明 | **未发现** 代码或文档中保留 AIRI 的版权声明 | ⚠ 若确有代码源自 AIRI，必须在 NOTICE 或源文件头补 MIT 声明 |

**待确认（需要你或上游核实）**：

1. 那 10,737 行是"照抄 AIRI"还是"照 Cubism 官方示例重写"？前者必须补 MIT 声明，后者只需 Cubism 声明。
2. 若确为 AIRI 代码，补一份 `NOTICE` 段落 + MIT 全文（这一步我可以代做，但要先确认事实）。

## 2. QQ 适配器

| 项 | 事实 | 结论 |
|---|---|---|
| 我们的实现 | 只实现 **OneBot v11 客户端**（WebSocket），不打包任何协议实现 | ✅ 无再分发义务 |
| 协议端 | NapCat / Lagrange / SnowLuma 由用户自行安装 | ✅ 不随包分发 |
| NapCat 许可 | 其许可证限制商业使用与打包分发 | ✅ 我们未打包，符合 |
| 代码依赖 | `src/shared/config-schema.ts` 明确注释"逻辑只依赖 OneBot v11，不依赖具体实现" | ✅ 干净 |

**注意**：QQ 协议端本身涉及腾讯服务条款风险（账号封禁），这是**产品风险**不是许可风险，已在文档与免责声明里说明。

### 变更：用户要求内置 NapCat 随包分发（2026-11-03）

| 问题 | 说明 |
|---|---|
| 与既有结论冲突 | ADR-5 明确记录 NapCat"许可禁止商用，不可打包" |
| 法律后果 | 若许可确实限制再分发，随包即侵权，且可能牵连整个发行版 |
| 需要什么才能放行 | 许可原文（含版本号）+ 允许再分发的条款 + 记入 approvals.json |
| 当前处理 | 按 D59.07 阻塞，**未随包分发** |
