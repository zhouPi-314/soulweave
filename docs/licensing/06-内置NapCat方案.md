# 内置 NapCat：许可结论与落地方案

> 2026-11-03 · 依据：NapCat 官方 LICENSE 原文（已在 VPN 下取得）

## 一、许可结论：**可以随包分发，但只能非商业**

原文要点（`third_party/napcat/LICENSE-napcat.txt` 全文）：

| 条款 | 内容 | 对我们意味着 |
|---|---|---|
| 2 再分发 | 允许，但须**附完整许可文本**并清楚标注来源与版权 | 安装包内附 `LICENSE-napcat.txt` + 仓库地址 |
| 2 修改 | 允许小改，但**修改版不得公开发布** | 我们**不改** NapCat，原样打包 |
| 3 非商业 | **不得用于任何商业目的** | ⚠ 一旦 SoulWeave 收费/带广告/商业分发，就必须先拿作者书面许可或移除 |
| 4 其他权利 | 未明确的权利需作者授予 | 不做衍生分发 |

**判定**：按当前「免费开源、不收钱」的发行方式，随包 ✅ 合法。
若将来商业化，必须先取得 Mlikiowa 的书面许可（条款 4）。

## 二、体积账（决定怎么打包）

NapCat 官方 v4.18.42 资产：

| 资产 | 大小 | 用途 |
|---|---|---|
| `NapCat.Framework.zip` | 35.1 MB | 核心框架（需已有 QQ 环境） |
| `NapCat.Shell.zip` | 34.3 MB | Shell 版 |
| `NapCat.Shell.Windows.Node.zip` | **118.4 MB** | 自带 Node 的完整 Windows 版（**推荐**） |
| `NapCat.Shell.Windows.OneKey.zip` | 0.9 MB | 一键脚本（运行时下载，不内置） |

现状安装包 254.9 MB。若内置完整版：**约 +118 MB → 373 MB**（解压后磁盘更多）。

三种方案：

| 方案 | 安装包增量 | 首启体验 | 许可 | 备注 |
|---|---|---|---|---|
| A. 内置完整版（推荐若坚持"开箱即用"） | +118 MB | 直接可用 | 需附许可 | 体积最大 |
| B. 内置 Shell 版（34 MB），首次运行下载 Node | +34 MB | 需联网一次 | 需附许可 | 体积/体验折中 |
| C. 不内置，首启引导安装（当前实现） | 0 | 需用户手动装 | 无义务 | 最省事，但你要改 |

## 三、我准备好的东西（还没执行下载）

- `scripts/fetch-napcat.mjs`：按固定版本下载 → 校验 SHA-256 → 解压到 `resources/napcat/` → 写 `version.json`
- `third_party/napcat/LICENSE-napcat.txt`：许可全文（随包必须）
- `NOTICE` 第 13 条：来源、版权、非商业条件
- `approvals.json`：napcat 已批准，附 3 条硬条件

**没有执行下载**，因为：118 MB 的二进制一旦进仓库/安装包，就不可逆地改变发行物；
且要先把"非商业"这条写进发行约定（见下）。

## 四、落地还需要你确认三件事

1. **选 A 还是 B**（+118 MB 还是 +34 MB）？
2. **确认发行保持非商业**（免费、无广告、不卖）——这是条款 3 的硬前提。
3. **QQ 账号风险**：随包分发协议端会让"用户自己承担封号风险"的免责表述变弱，
   需要在首启向导里加一段显式确认（我可以写）。

确认后我会：
1. 跑 `node scripts/fetch-napcat.mjs --variant full` 下载并校验；
2. 在 `electron-builder.yml` 加 `resources/napcat` → `napcat`；
3. 主进程加启动/停止/健康检查（复用现有 OneBot 客户端，不改协议层）；
4. 首启向导加"协议端"步骤 + 风险确认；
5. 打包验证：安装包内能看到 `resources/napcat/LICENSE-napcat.txt`。
