# 主项目许可证决策（D59.01）

> 状态：**待用户批准**。本文件只列选项与影响，不替你做决定。

## 为什么需要一个明确的许可证

1. 没有 LICENSE 文件，默认是"保留所有权利"——别人连读、改、二次分发都不被允许。
2. 官网、README、Release 都要引用它；没有它，文档里"开源"的说法站不住。
3. 依赖侧已经干净（402 个包，0 个 copyleft），所以选择权完全在项目自己手里。

## 三个现实选项

| 选项 | 适用情形 | 后果 |
|---|---|---|
| **MIT** | 想让人随便用、随便改，包括商用 | 最简单、最宽松；别人可以闭源分发你的代码，只需保留版权声明 |
| **Apache-2.0** | 想宽松但要求专利授权与修改声明 | 比 MIT 多专利条款与 NOTICE 要求；企业用户更愿意接受 |
| **AGPL-3.0** | 想要求"改了就必须开源"，包括网络服务 | 与"卖桌面软件"冲突最小，但会挡住一部分商业集成，社区接受度低 |

## 我的建议（仅供参考）

倾向 **MIT + 独立的素材许可说明**：

- 代码用 MIT，降低使用门槛；
- **模型权重、Live2D 素材、音色不自动继承 MIT**，单独在 `NOTICE` 与素材清单里声明各自的许可（见 `02-素材与模型.md`）；
- 品牌名与图标不授权商标使用（可在 NOTICE 里写明"名称与图标仅用于标识本项目"）。

理由：这个项目的价值在角色与素材，不在代码保密；代码宽松 + 素材严格，是这类项目最常见的组合。

## 待你确认的三件事

1. 代码许可证选哪个（MIT / Apache-2.0 / AGPL-3.0 / 其他）。
2. 是否接受"素材不随代码许可证"这一拆分（D59.06 要求分开管理）。
3. 是否允许在未完成商业授权的情况下先以"个人非商业"方式发布。

> 你确认后，我会：写 `LICENSE`、把 `licensing/assets.json` 里 `code-app` 标成已批准、并让 `npm run license:gate` 放行。
