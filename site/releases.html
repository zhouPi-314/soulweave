把版本事实分开写清楚

规划基线、开发候选和开发里程碑不是同一个概念。版本号与日期也是两个字段，不应拼成一个字符串。

规划基线 V1.7（规划基线）

项目需求与阶段规划使用的内部基线，不是安装包版本，也不是公开版本号。

开发候选 0.1.0-s1

当前 Windows 公开候选版本，发布日期为 2026-11-03。安装包通过 GitHub Releases 分发。

开发里程碑 0.1.0-s0

核心能力建立阶段记录，用于说明开发进展，不代表可供公众安装的版本。

公开发布状态：公开候选版。 安装包可在 GitHub Releases 下载，但尚未进行商业代码签名；下载后请核对 SHA-256。

Version Format

版本信息冲突处理

已确认

V1.7 是需求与阶段规划基线；0.1.0-s1 是当前应用与站点数据记录的产品候选版本；0.1.0-s0 是开发里程碑。

不要拼接

0.1.0-s1 后的日期是元数据中的独立字段。将它拼成连续版本字符串会产生错误，也会让用户误以为日期属于版本号本身。

下载页原先同时写有“内部版本 V1.7”和候选版本号。界面现已改为统一的发布状态表述；真实版本号没有被修改。
